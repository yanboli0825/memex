    项目结构

    Introduction¶

    本人在入组之后做了很长一段时间的C++桌面软件开发工作。由于组里对项目结构没有经验积累，导致项目的整个结构非常松散，各个模块的接口、源代码、资产文件（如AI模型、视频、图片、音频等）混在一起，对软件开发带来了一定的困难。

    在饱受折磨之后，本人结合仅有的开发经验和网络资源，整理了一套面向Visual Studio 2022的Windows桌面软件开发项目结构。该结构既有一定的层次，又不至于过度封装，对于软件开发小白上路比较友好。当然，由于时间、开发经验等的限制，该项目结构也一定存在不足之处。若时间、精力、项目允许，本人会根据实践经验不断调整项目结构，以期实现一个兼具易用性和模块化的项目结构。

    Constraints¶

    本文讨论的C++项目结构基于以下条件：

    • Visual Studio 2022 IDE（MSVC工具链）
    • x64架构的桌面应用程序

    基于其他开发条件的读者可以根据本文的项目结构进行适当调整。

    Implementation¶

    项目结构如下： 

    ProjectName
|
|-build
|   |
|   |-Debug/Release
|   |   |
|   |   |-x64
|   |      |
|   |      |-bin
|   |      |-obj
|   |      |-(other needed dirs)
|   |-dist
|       |
|       |-bin
|       |-(other needed dirs)
|
|-sources
|   |
|   |-3rdparty
|   |-bin
|   |-docs
|   |-etc
|   |-include
|   |-lib
|   |-res
|   |-src
|
|-README.md
|-ProjectName.sln
|-ProjectName.vcxproj
|-ProjectName.vcxproj.filters
|-ProjectName.vcxproj.user
|-.vs
|-.gitignore
|-(other vs files)

    项目结构说明： build是构建文件，用于存放与程序构建相关的内容；dist文件用于存放分发文件，该文件是可以直接交付给用户使用；Debug/Release存放对应开发配置产生的文件；x64为程序应用平台；bin存放Debug或Release产生的二进制文件，例如.exe、.lib、.dll等文件；obj存放编译等过程中产生的中间文件，如.obj文件；(other needed dirs)用于存放运行程序时（运行.exe文件时，运行时目录为.exe文件所在的目录，若程序中使用了一些相对路径，则需要将这些相对路径下的文件复制到运行时目录相对应的位置）所需的一些文件，例如配置文件、资产文件等。

    sources是源文件。3rdparty用于存放第三方库等文件，这样在移动或交付源代码时就无需重新安装了；bin文件存放程序开发使用的一些二进制文件，如实验室或其他公司开发的.dll文件；lib文件用于存放实验室或其他公司开发的.dll文件；docs文件用于存放代码说明文档；include文件用于存放头文件；src用于存放cpp文件；res文件用于存放资产文件，例如AI模型、视频、音频、图片等；etc文件用于存放其他需要的文件，如用户配置文件等。

    VS的.sln、.vcxproj等文件存放在根目录里，防止污染build文件和sources文件。.gitignore文件在将项目上传至github等托管平台时可以设置过滤.vs、build等文件，减小文件的上传体积。
